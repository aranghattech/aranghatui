# CLAUDE.md — artui (aranghatui)

Operating manual for Claude in this repository. Read fully before any task. Never skip the **Definition of Done** gate.

---

## 1. What this is

- `artui` = AranghatUI. A framework-agnostic design system + component library.
- Consumed by **all** our SaaS apps → consistency and API stability outrank feature velocity.
- Authored once in **Stencil** (Web Components), distributed to **HTML, React, Vue, Angular** via output targets.
- Visual language, density, motion and polish follow **shadcn/ui** closely. We do not clone its code (React/Radix); we match its craft.

### Non-negotiables (North Stars)

| # | Rule |
|---|---|
| N1 | Bundle size is a first-class feature. Every component has a gzip budget. No component ships over budget without an ADR. |
| N2 | Full parity with `https://ui.shadcn.com/docs/components` — **except Chart**. |
| N3 | Every component is visually regression-tested before the next one starts. One component in flight at a time. |
| N4 | One radius scale, one border width, one border colour — applied uniformly. No per-component exceptions. |
| N5 | Stencil is the single source of authorship. No hand-written React/Vue/Angular components, ever. |
| N6 | Zero hardcoded design values in components. Tokens only. |

### Per-tier packaging (why)

Apps install only the tiers they need. A marketing site takes `base` and nothing else; an internal admin app takes everything.

| Package | Depends on |
|---|---|
| `@aranghat/tokens` | — |
| `@aranghat/primitives` | tokens |
| `@aranghat/base` | tokens |
| `@aranghat/components` | tokens, primitives, base |
| `@aranghat/navigation` | tokens, primitives, base |
| `@aranghat/modals` | tokens, primitives, base |
| `@aranghat/widgets` | all of the above |

- Framework packages mirror this exactly: `@aranghat/base-react`, `@aranghat/components-react`, `@aranghat/navigation-vue`, `@aranghat/modals-angular`, etc.
- Cross-tier deps are **peerDependencies + devDependencies**, never `dependencies`. A tier must never bundle a lower tier — that would duplicate components in the consumer's graph.
- `@aranghat/ui` is a convenience meta-package that re-exports every tier. Documented as the "just get me started" option, with an explicit note that it costs bundle size. Nothing internal may depend on it.
- **Custom element registration must be idempotent.** Every `define()` is guarded (`if (!customElements.get(tag))`) so two tiers, or two versions in the same page, cannot throw. Enforced by a shared `defineCustomElement` helper in `primitives`.
- All `@aranghat/*` packages are released **in lockstep at one version**. Mixed versions across tiers is the single most likely source of duplicate-registration and token-drift bugs.
- Moving a component between tiers is a **breaking change**. Decide the tier before implementing.

## 3. Naming and conventions

- npm scope: `@aranghat/*`. The design system's name stays **artui**; the published scope is `@aranghat`.
- Custom element prefix: `art-` → `<art-button>`, `<art-dropdown-menu-item>`. Required — custom elements are global, the prefix prevents collisions in host apps.
- CSS custom property prefix: `--art-`.
- Files: `packages/<tier>/src/<component>/` containing
  `art-<component>.tsx`, `art-<component>.css`, `art-<component>.spec.tsx`, `art-<component>.e2e.ts`, `readme.md` (auto-generated by Stencil — never edit by hand).
- Props: camelCase in TSX, kebab-case as attributes. Booleans default `false`.
- Slots: named slots for all composition. `start`, `end`, `label`, `description`, `header`, `footer`. Avoid prop-passed markup.
- Sizes are always `sm | md | lg` with `md` the default. Never invent `xs`/`xl` per component.
- Variants for interactive components: `default | secondary | outline | ghost | destructive | link` (subset per component, never renamed).

## 3a. Framework API — idiomatic, unprefixed

**The `art-` prefix stops at the custom-element boundary.** In every framework binding, the component is named and behaves the way a developer of that framework expects.

| | HTML | React | Vue | Angular |
|---|---|---|---|---|
| Component | `<art-button>` | `<Button>` | `<Button>` | `<art-button>` |
| Import | `@aranghat/base` | `@aranghat/base-react` | `@aranghat/base-vue` | `@aranghat/base-angular` |
| Click | `addEventListener('click')` | `onClick` | `@click` | `(click)` |
| Value | `value` attr | `value` / `onChange` | `v-model` | `[(ngModel)]` / reactive forms |
| Open state | `open` attr + `open-change` | `open` / `onOpenChange` | `v-model:open` | `[open]` / `(openChange)` |

React name collisions are the consumer's problem to alias (`import { Button as ArtButton }`), not ours to pre-solve with a prefix.

### Event rules

1. **Native events stay native.** If a component wraps a real control, the native event is the public event. `click`, `input`, `change`, `focus`, `blur`, `submit`, `keydown`.
    - `input`, `change`, `reset` and `submit` do **not** cross the shadow boundary by default. Every component wrapping a native control must **re-dispatch them from the host** with `{ bubbles: true, composed: true }`, retargeted so `event.target` is the `<art-*>` element. This is mandatory and tested.
    - Form-associated controls (Input, Checkbox, Radio, Switch, Select, Textarea, Slider, Toggle) implement **ElementInternals / `formAssociated`** so they work inside a plain `<form>` and with FormData.
2. **Custom events use plain, unprefixed, lowercase kebab-case names** on the web component: `open-change`, `value-change`, `select`, `dismiss`, `close`, `expand`, `collapse`, `reorder`. Kebab-case is mandatory, not stylistic: Stencil's React and Angular output targets derive `onOpenChange` and `(openChange)` from the hyphen, whereas `openchange` would generate `onOpenchange` and `(openchange)` (ADR-0001).
3. **Only prefix on a genuine collision** with a native event name where native semantics cannot be preserved. The prefixed form is `art-select`, `art-close`. Any use requires a line in `docs/conventions/event-collisions.md` explaining why.
    - Known collision watchlist: `select` (native on text inputs), `close` (native on `<dialog>`/`<details>`), `toggle` (native on `<details>`/popover), `cancel`, `search`. Check this list before naming an event.
4. **Stencil config does the mapping**, not hand-written code:
    - React output target: `onOpenChange`, `onValueChange` (`on` + kebab-case event name camel-cased, generated automatically), `onClick` passes through natively.
    - Vue output target: `componentModels` (`elements` / `targetAttr` / `event`) configured per component so `v-model` works out of the box.
    - Angular output target: `valueAccessorConfigs` for every form control so `ngModel` and reactive forms work.
5. All custom events are `CustomEvent<T>` with a typed, documented `detail`. `detail` is never the raw DOM event.
6. Event names are part of the public API — renaming one is a breaking change.

## 4. Token pipeline (Tier 1)

**Style Dictionary is the only place a design value may be born.**

### Token tiers

1. **Primitive** — raw scales. `--art-color-slate-500`, `--art-space-4`, `--art-radius-md`. No semantics, never used in components.
2. **Semantic** — intent. `--art-color-bg-surface`, `--art-color-fg-muted`, `--art-color-border-default`, `--art-color-accent-solid`. **This is what components consume.**
3. **Component** — only when a component needs a value with no semantic equivalent. `--art-button-height-md`. Must reference a semantic or primitive token, never a literal.

### Rules

- Source of truth: `packages/tokens/src/**/*.json` (DTCG format, `$value` / `$type`).
- Build targets: `css` (custom properties), `scss`, `js`/`ts` (typed), `json`, `compose` (Android), `swift` (iOS).
- Theming: light/dark emitted as `:root` and `[data-theme="dark"]` + `@media (prefers-color-scheme: dark)` guarded so an explicit `data-theme="light"` wins.
- **Shadow DOM note:** CSS custom properties inherit through shadow boundaries. This is the mechanism that lets one `:root` token sheet theme every component. Do not redefine tokens inside a component's shadow root.
- Brand themes per SaaS app = an override sheet that redefines **semantic** tokens only.

### Tailwind binding

- Tailwind v4. `@theme` maps utility names to the generated `--art-*` custom properties.
- Components are authored with Tailwind utilities; Tailwind is compiled **per-component into the shadow stylesheet** at build time. No global stylesheet dependency for consumers, except the token sheet.
- Consumers must import exactly one CSS file: `@aranghat/tokens/aranghat.css`.
- **Forbidden in component CSS/TSX:** hex/rgb/hsl literals, `px` values outside a token, arbitrary Tailwind values (`w-[13px]`, `text-[#fff]`), `!important`.

### The one-border rule (N4)

- `--art-border-width: 1px` — every bordered surface uses it.
- `--art-color-border-default` — every border colour, with `--art-color-border-strong` reserved for focus/selected states only.
- `--art-radius` is the single base; components derive `sm/md/lg` via `calc()` off it. Changing `--art-radius` restyles the whole system.

## 6. `@aranghat/primitives` (internal)

Shared headless logic. Written once, reused everywhere — this is the main lever for both bundle size and behavioural consistency.

- `floating` — positioning, flip/shift/arrow. Wraps `@floating-ui/dom` (only approved third-party runtime dep).
- `dismissable` — outside-click, escape, scroll-lock.
- `focus-trap` — modal focus containment + restore.
- `roving-tabindex` — menus, tabs, toolbars, tree.
- `portal` — overlay host element management, single shared layer stack with z-index tokens.
- `typeahead` — listbox/menu keyboard search.
- `id` — SSR-stable unique IDs for aria wiring.
- `date` — internal date math for Calendar/Date Picker. **Do not add date-fns/dayjs/luxon.**

Rule: if two components need the same behaviour, it moves into `primitives` before the second one ships.

## 7. Bundle discipline (N1)

Two levers: **tier packages** (don't install what you don't need) and **tree-shaking** (don't bundle what you don't import). Both must work; neither is a substitute for the other.

- Output target: `dist-custom-elements` with `externalRuntime: false` and `customElementsExportBehavior: 'single-export-module'`, tree-shakable. The Stencil runtime is inlined per tier because that is the only form Stencil tree-shakes by feature use (~7 kB gzip per tier vs ~25 kB for the shared external runtime — measured, ADR-0002). `@stencil/core` is a devDependency pinned to one exact version across tiers. Do **not** use the lazy-loader `dist` target as the primary consumer path.
- Every component is independently importable within its tier: `import { Button } from '@aranghat/base-react/button'`.
- Side-effect free. `"sideEffects": ["**/*.css"]` in every package.json.
- **Budgets (gzip, per component, excluding shared primitives):**
    - Tier 2 atom: ≤ 3 kB
    - Tier 3 composite: ≤ 8 kB
    - Data Table / Calendar / Command: ≤ 15 kB
    - Stencil runtime + primitives total: ≤ 20 kB
- **Package budgets (gzip, full tier imported):** base ≤ 45 kB · components ≤ 90 kB · navigation ≤ 45 kB · modals ≤ 30 kB · widgets ≤ 60 kB.
- **Reference app budgets**, tracked in CI as the real-world proof:
    - Landing page (`base` only, ~6 components): ≤ 15 kB
    - Auth screen (`base` + `widgets/login`): ≤ 30 kB
    - Full admin shell (all tiers): ≤ 180 kB
- `size-limit` runs in CI and fails the build on regression. Budgets live in `.size-limit.json`.
- Approved runtime deps: `@floating-ui/dom` (primitives) and `embla-carousel` (Carousel only, ADR-0005). Anything else requires an ADR.
- Icons are not bundled into components — passed via slot, or imported individually from `@aranghat/icons`.

## 8. Visual & interaction quality bar

Match shadcn's restraint. Specifically:

- **Motion:** micro only, user-triggered. `--art-duration-fast: 120ms`, `--art-duration-base: 180ms`, `--art-ease-out`. Enter/exit for overlays; state change for toggles; nothing decorative. All motion gated on `@media (prefers-reduced-motion: reduce)`.
- **Focus:** single global focus-ring recipe — `--art-ring-width`, `--art-ring-color`, `--art-ring-offset`. Identical on every focusable element. `:focus-visible` only.
- **Elevation:** 3 shadow tokens max (`raised`, `overlay`, `popover`). No per-component shadows.
- **States:** every interactive component implements `hover / active / focus-visible / disabled / loading / invalid` — all six, or documents why not.
- **Density:** control heights derive from a single `--art-control-height-{sm,md,lg}` set so Input, Select, Button and Combobox align pixel-perfectly when side by side.
- **Dark mode is not an afterthought** — both themes are screenshot-tested in the same run.
- No ALL-CAPS labels, no decorative gradients, no per-card shadows.

## 9. Testing — the gate

**No component is "done", and no new component may start, until all of the following pass.**

### Definition of Done (per component)

- [ ] Stencil **spec tests** — rendering, props, events, slots.
- [ ] Stencil **e2e tests** — keyboard interaction, full ARIA pattern per WAI-ARIA APG.
- [ ] **Visual regression** — Playwright screenshots, `maxDiffPixelRatio: 0.001`, across the matrix:
    - themes: light, dark
    - viewports: 390, 768, 1280
    - states: default, hover, focus-visible, active, disabled, loading, invalid
    - every documented variant × size
    - RTL pass for anything directional
- [ ] **Accessibility** — axe-core zero violations; manual keyboard walkthrough recorded in the PR; screen-reader labels verified.
- [ ] **Token lint** — `pnpm lint:tokens` passes (no literals, no local tokens).
- [ ] **Size check** — within budget.
- [ ] **Cross-framework smoke** — rendered in all four sandbox apps (HTML, React, Vue, Angular), using the idiomatic API from §3a.
- [ ] **Event contract** — native events verified to cross the shadow boundary with correct `target`; `v-model` and `ngModel`/reactive-forms verified for any form control; no unnecessary `art` prefix.
- [ ] **Tier placement** — component is in the correct package and adds no new cross-tier dependency.
- [ ] **Docs page** complete and matching the template (§10).
- [ ] Baselines committed; diff images reviewed, never blind-approved.

### Commands

```bash
pnpm test:unit        # Stencil spec
pnpm test:e2e         # Stencil e2e
pnpm test:visual      # Playwright VRT
pnpm test:visual -u   # update baselines (requires explicit human approval)
pnpm test:a11y        # axe
pnpm lint:tokens      # token discipline
pnpm size             # size-limit
pnpm verify           # all of the above — this is the gate
```

## 10. Documentation (VitePress)

`apps/docs`. Every component page uses the **identical** structure — no exceptions, no reordering:

1. **Title + one-line description**
2. **Preview** — live, interactive web component embed that follows the page's light/dark mode (RTL and brand toggles on the frame)
3. **Installation** — the tier package this component lives in, plus the install + import line for each framework
4. **Usage** — tabbed code blocks: `HTML | React | Vue | Angular`, all four always present, all four copy-pasteable and verified against the sandbox. Each tab uses that framework's idiomatic form per §3a (`onClick`, `@click`, `v-model`, `(click)`) — never the web-component form dressed up.
5. **Examples** — one section per variation, each with live preview + 4-framework tabs. **Every documented variant, size and state must appear here.**
6. **API Reference** — auto-generated from Stencil's `readme.md`: Props, Events, Methods, Slots, CSS Custom Properties, CSS Shadow Parts
7. **Accessibility** — keyboard map table, ARIA roles, APG link
8. **Tokens used** — table of every semantic token the component consumes
9. **Do / Don't** — visual guidance pairs

Additional rules:
- Docs are written from the same source data as the tests. If a variant exists in the VRT matrix it must exist on the page, and vice versa — `pnpm verify:docs-parity` enforces this.
- Code samples are extracted from real files in `apps/sandbox`, never typed inline into markdown.
- Sidebar order mirrors the tier hierarchy in §5.
- Also maintained: `Getting Started`, `Theming`, `Tokens`, `Dark Mode`, `RTL`, `Bundle Size`, `Migration`, `Contributing`.

## 12. Workflow Claude must follow

**One component at a time. Never start the next until `pnpm verify` is green and merged.**

1. Read this file and the relevant repo-local skill.
2. Restate the component's scope: variants, sizes, states, slots, events, ARIA pattern.
3. Check shadcn's page for the same component and note behaviour/visual parity points.
4. Check `primitives` — reuse before writing. If new shared logic is needed, land it in `primitives` first as its own change.
5. Confirm every design value exists as a **semantic token**. If not, add the token first (separate commit).
6. Implement in Stencil. Shadow DOM on by default; document `::part()` and CSS custom property hooks for consumer overrides.
7. Run `better-ui` pass. Screenshot, critique, refine.
8. Write tests → run the full matrix → review diffs visually.
9. Write the docs page and the four sandbox samples.
10. `pnpm verify`. Report bundle delta.
11. Summarise: what shipped, tokens added, bundle delta, deviations from shadcn and why.

### Hard rules for Claude

- Never hardcode a colour, spacing, radius, duration or font value.
- Never add an `art` prefix to a React/Vue component name or to an event that has no collision.
- Never invent a custom event where a native one exists — re-dispatch the native one instead.
- Never re-implement a control the platform provides. A checkbox is `<input type="checkbox">`, a slider is `<input type="range">`: wrap the native element, style it with `appearance: none` + pseudo-elements, keep its behaviour (ADR-0020). Custom interaction only where no native element exists (Toggle, Tabs, Combobox…).
- Never add a cross-tier dependency that points downward (base must not import from components).
- Never list a sibling `@aranghat/*` package under `dependencies` — peer + dev only.
- Never introduce a runtime dependency without an ADR in `.claude/adr/`.
- Never hand-author a React/Vue/Angular component — regenerate wrappers instead.
- Never edit Stencil-generated `readme.md` or `components.d.ts`.
- Never change an existing visual baseline without explicit human approval. The first baselines of a brand-new component may be committed after every image has been reviewed and the review is noted in the PR (ADR-0015).
- Never rename or remove a public prop/event/slot without a deprecation cycle and a migration note.
- Never add a variant that doesn't exist in shadcn unless explicitly requested — API surface is a cost.
- If a shadcn behaviour conflicts with a token rule, raise it rather than silently diverging.

## 14. Decisions (resolved 2026-09-14 — see `.claude/adr/`)

| Decision | Resolution | ADR |
|---|---|---|
| Custom event naming | Lowercase kebab-case on the DOM (`open-change`); output targets derive `onOpenChange` / `(openChange)` / `@open-change` | 0001 |
| Stencil runtime | Inlined per tier (`externalRuntime: false`) — measured 12 kB vs 25 kB for a base-only page; `@stencil/core` stays a pinned devDependency | 0002 |
| Shadow vs `scoped` for widgets | Shadow DOM everywhere; a widget that needs global layout gets its own ADR | 0003 |
| Token CSS distribution | One `aranghat.css` (default theme, light + dark); brand themes as separate override files | 0004 |
| Carousel | `embla-carousel` (second approved runtime dep) | 0005 |
| Data Table | Headless only: `table-state` primitive + styled Table + documented composition recipe | 0006 |
| Icon strategy | Per-icon ES modules + one generic `<art-icon>`; no sprite sheet | 0007 |
| React 19 native custom elements | Keep generated wrappers; revisit at Phase 8 | 0008 |
| Stencil project layout | Five independent Stencil projects, one per tier | 0009 |
| Widgets distribution | Compiled components | 0010 |
| Widgets entry points | Subpaths (`@aranghat/widgets/login`) | 0011 |
| Button API | Strict shadcn: `default` = primary fill; no extra variants or props | 0012 |
| Brand font | System font stack; no shipped font files | 0013 |
| Brand themes | Neutral default first; the six brand themes are re-ported later as override sheets | 0014 |
| Git workflow and baselines | Branch per component, PR, self-merge on green; initial baselines committed after review | 0015 |
| Publishing | Nothing published before 1.0; Changesets configured, lockstep | 0016 |
| Tier 3 dependency on `base` | Allowed (peer + dev), matching §5 | 0017 |
| Screenshot determinism | VRT and a11y run in the official Playwright Docker image locally and in CI; Linux-only baselines | 0018 |
| Cross-tier composition | No downward deps: Command has no built-in dialog mode; Sidebar mobile mode is built on primitives, not Sheet | 0019 |
| Native controls first | Wrap and style the native element wherever HTML has one (`input` types, `select`, `textarea`, `button`, `progress`, `dialog`, `details`); custom logic only where no native exists or to orchestrate natives across shadow roots | 0020 |

**Also resolved:** versioning is fixed/lockstep across all `@aranghat/*` packages (§2).
